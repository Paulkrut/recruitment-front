# Краткая сводка: Исправление Out of Memory в списке кандидатов

## Проблема
Ошибка `Out of Memory` (256MB лимит исчерпан) при загрузке страницы `/hr/candidates`

## Причина
- Загружались ВСЕ кандидаты сразу (без пагинации на бэкенде)
- Для каждого кандидата загружались все ответы с attachments и транскрибациями
- При 100+ кандидатах это приводило к OOM

## Решение

### Backend (`AdminAllCandidatesController.php`)
✅ Добавлена серверная пагинация (default: 20 записей на страницу)
✅ Оптимизация запросов: загружаются только минимальные поля для подсчета score
✅ Серверные фильтры: статус, поиск, вакансия
✅ Серверная сортировка
✅ Новый формат ответа: `{ data, total, page, limit, totalPages }`

### Frontend (`candidates/page.tsx`)
✅ Обработка нового формата API с пагинацией
✅ Передача фильтров на сервер (кроме score)
✅ Отображение `totalCandidates` вместо `candidates.length`

## Результат
- 📉 Память: 256+ MB → ~20-30 MB (10x экономия)
- ⚡ Скорость: в 5-10 раз быстрее
- ✅ Масштабируемость: работает с любым количеством кандидатов
