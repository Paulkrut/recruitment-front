## История: доступ до подключения API

Не удалось получить агрегированные отчёты: это требует авторизованного доступа к аккаунту Метрики либо OAuth-токена API с правами на счётчик. Публичный ID счётчика не предоставляет доступ к персональным отчётам. Я не использовал сохранённые браузерные сессии/чужие credentials и не делал выводов о трафике, конверсиях, источниках или рекламных расходах.

Чтобы продолжить, владелец может предоставить один из безопасных вариантов:

1. Добавить пользователя-аудитора в счётчик на чтение и открыть авторизованную сессию Метрики в браузере.
2. Выгрузить отчёты CSV/XLSX за период и приложить их в чат/проект.
3. Передать OAuth-токен с минимально необходимым read-only доступом к нужному счётчику через согласованный безопасный канал (не коммитить секрет в репозиторий и не вставлять в исходники).

После доступа полезно получить период 90 дней и сравнение год-к-году (если данные есть): источники, поисковые запросы, посадочные, устройства, регионы, цели, отказы/глубина, новые/возвратные, рекламные кампании и расходы.

## Выбранный способ: API Метрики

Пользователь выбрал API. По официальной документации https://yandex.ru/dev/metrika/ru/intro/authorization требуется OAuth-приложение типа «Для доступа к API или отладки» с единственным правом `metrika:read`. Для porg-аккаунта дополнительно требуется `passport:business`. Аккаунт, выдающий токен, должен иметь доступ к счётчику; OAuth-scope не ограничивает токен одним счётчиком, поэтому предпочтителен отдельный Яндекс-аккаунт с гостевым доступом на просмотр только нужного счётчика.

ClientID приложения не секрет: его можно сообщить для формирования ссылки авторизации. OAuth-токен — секрет: не передавать в чат/URL API, не записывать в git; использовать локальное защищённое хранение вне репозитория или переменную окружения `YANDEX_METRIKA_TOKEN`. Авторизация запросов: HTTP-заголовок `Authorization: OAuth <token>`.

Первый запрос — чтение доступных счётчиков `/management/v1/counters`, затем настройки/цели счётчика `103628640` и агрегированные отчёты `/stat/v1/data`. Отчётный период: 90 полных дней до 28 октября 2026 включительно, сравнение с предыдущим сопоставимым периодом. Учитывать sampling/точность, timezone, пагинацию и фильтрацию роботов; не выгружать Webvisor или персональные данные кандидатов. Схему целей ниже считать предложением до чтения реальных настроек счётчика: цели могут быть настроены в кабинете без явного `reachGoal` в коде.

## Рекомендуемая схема целей

Не передавать в аналитику резюме, ФИО кандидатов, содержимое интервью, email, телефон или другие персональные данные. Использовать только обезличенные события и категории.

### Сайт и SEO-инструменты

- `hr_tool_open` — открытие страницы инструмента (`tool_id` из allowlist).
- `hr_tool_start` — начало работы.
- `hr_tool_result` — результат сформирован.
- `hr_tool_download` — файл скачан (тип документа без пользовательских данных).
- `product_signup_start` / `product_signup_complete` — начало/успех регистрации.
- `demo_request_start` / `demo_request_complete` — запрос демо отправлен.

### B2B-активация (если события можно безопасно передать из продукта)

- `company_created` — компания/пространство создано.
- `vacancy_created` — создана первая вакансия.
- `candidate_added` — добавлен первый кандидат; только факт события, без идентификаторов или данных кандидата.
- `first_interview_completed` — завершено первое интервью; без ответов/расшифровки.
- `subscription_started` — успешная оплата, с суммой/валютой только если это допустимо политикой аналитики и нет привязки к личности.

События считать выполненными только после проверки вызовов в интерфейсе Метрики/отладчике. Не отправлять события загрузки/отправки персональных данных и не считать клик по CTA эквивалентом состоявшейся регистрации/оплаты.

## Рекомендуемые отчёты после получения доступа

1. **Воронка инструментов:** landing → старт → результат → скачивание → переход к платформе → регистрация.
2. **B2B-воронка:** источник/кампания → целевая страница → demo/signup → первая вакансия → первое интервью → повтор → оплата.
3. **Посадочные органики:** показы/клики из Вебмастера/Метрики по URL, новые и возвращающиеся посетители, целевые события.
4. **Качество трафика:** канал × устройство × регион × посадочная; не оценивать по отказам без учёта SPA-переходов и характера инструмента.
5. **Директ:** кампания/ключевая фраза/поисковый запрос, расход, клики, конверсии по целям и стоимости; сверять расходы с кабинетом Директа.
6. **Сегментирование:** платформа vs бесплатные HR-инструменты, без смешивания их конверсий в один общий показатель.
