# ⏱️ Индивидуальное время ответа для вопросов

## Проблема

Раньше все вопросы вакансии имели **одинаковое время** на ответ. Это неудобно, когда:
- Простой вопрос требует 1 минуту, а сложный — 5 минут
- Вопрос с видео/аудио материалом требует больше времени на просмотр
- Вопрос с кодом требует больше времени на решение

## Решение

Добавлена возможность настройки **индивидуального времени** для каждого вопроса в **экспертном режиме**.

### Ключевые особенности

✅ **Компактный UI** — не перегружает интерфейс  
✅ **Умная синхронизация** — глобальное время не перезаписывает кастомные настройки  
✅ **Визуальные индикаторы** — понятно, какие вопросы с индивидуальным временем  
✅ **Быстрый сброс** — одна кнопка для возврата к глобальному времени

---

## UI компоненты

### 1. Глобальное время (QuestionTimeSettings)

Находится в основных настройках вакансии:

```typescript
<QuestionTimeSettings
  value={templateData.questionTime}
  onChange={(newTime) => {
    const oldGlobalTime = templateData.questionTime;
    setTemplateData({ ...templateData, questionTime: newTime });
    
    // 🧠 Умная логика обновления
    setQuestions(questions.map(q => 
      q.maxTime === oldGlobalTime 
        ? { ...q, maxTime: newTime }  // Обновляем "дефолтные"
        : q                            // Оставляем "кастомные"
    ));
  }}
/>
```

### 2. Индивидуальное время (в QuestionFormItem)

Показывается в **экспертном режиме** для каждого вопроса:

- 🎚️ **Слайдер** (30-600 сек) с метками времени
- 🔢 **Числовое поле** для точного ввода
- ⏱️ **Отображение MM:SS** (например, "3:00")
- 🔄 **Кнопка сброса** (если время отличается от глобального)
- 📍 **Визуальная индикация:**
  - Синяя рамка — индивидуальное время
  - Серая рамка — глобальное время
  - Бейдж "Индивидуальное" — для кастомных значений

## Логика взаимодействия

### Сценарий 1: Изменение глобального времени

```
Глобальное время: 180 сек

Вопросы:
  Вопрос 1: 180 сек (следует за глобальным)
  Вопрос 2: 300 сек (индивидуальное)
  Вопрос 3: 180 сек (следует за глобальным)

Изменяем глобальное время → 240 сек

Результат:
  Вопрос 1: 240 сек ✅ (обновился)
  Вопрос 2: 300 сек ⏸️ (не тронут - кастомное)
  Вопрос 3: 240 сек ✅ (обновился)
```

**Логика:**
- Вопросы с `maxTime == oldGlobalTime` → обновляются
- Вопросы с `maxTime != oldGlobalTime` → остаются как есть

### Сценарий 2: Установка индивидуального времени

```
1. Открываем экспертный режим
2. Находим вопрос с глобальным временем (180 сек)
3. Изменяем слайдер/поле → 420 сек
4. Вопрос становится "кастомным"
5. Появляется бейдж "Индивидуальное" и кнопка сброса
```

### Сценарий 3: Сброс на глобальное

```
1. Вопрос имеет индивидуальное время (420 сек)
2. Нажимаем кнопку "🔄" (сброс)
3. Время сбрасывается на глобальное (180 сек)
4. Вопрос снова "следует" за глобальным
```

## Технические детали

### Props в QuestionFormItem

```typescript
interface QuestionFormItemProps {
  // ... существующие props
  globalMaxTime?: number;  // NEW: Глобальное время для индикации
}
```

### Проверка "кастомности"

```typescript
const isCustomTime = globalMaxTime && question.maxTime !== globalMaxTime;
```

### Компоненты UI

```typescript
// Визуальная индикация
borderColor: isCustomTime ? '#1976d2' : '#e0e0e0'
background: isCustomTime 
  ? 'linear-gradient(to right, #e3f2fd 0%, #f5f5f5 100%)' 
  : '#fafafa'

// Кнопка сброса (показывается только для кастомных)
{isCustomTime && (
  <IconButton onClick={() => onUpdate(index, "maxTime", globalMaxTime)}>
    <IconRefresh />
  </IconButton>
)}
```

## Структура данных

### Frontend (QuestionDraft)

```typescript
interface QuestionDraft {
  // ...
  maxTime: number;  // Время в секундах (например, 180)
}
```

### Backend (InterviewQuestion)

```php
class InterviewQuestion {
    // ...
    
    #[ORM\Column(type: 'integer', nullable: true)]
    private ?int $maxTime = null; // Секунды
}
```

### Поток данных

```
1. Создание вакансии:
   User устанавливает глобальное время (180 сек)
   ↓
   Все вопросы создаются с maxTime = 180
   ↓
   В экспертном режиме можно изменить для каждого

2. Редактирование вакансии:
   User загружает вопросы из БД
   ↓
   Каждый вопрос имеет свой maxTime
   ↓
   Глобальное время = maxTime первого вопроса (или 180 по умолчанию)
   ↓
   Изменения глобального времени применяются умно
   
3. Прохождение интервью:
   Кандидат получает вопрос
   ↓
   Таймер использует question.maxTime
   ↓
   Каждый вопрос имеет индивидуальный таймер
```

## Преимущества решения

### 🎯 UX

1. **Не перегружает интерфейс**
   - Скрыто в экспертном режиме
   - Компактный layout (слайдер + поле в одной строке)

2. **Понятная индикация**
   - Синий цвет = кастомное
   - Серый цвет = глобальное
   - Текстовая подсказка внизу

3. **Быстрое управление**
   - Слайдер для быстрой настройки
   - Числовое поле для точности
   - Кнопка сброса для возврата к дефолту

### 🧠 Логика

1. **Умная синхронизация**
   - Глобальное время не "ломает" кастомные настройки
   - Массовое обновление только для "дефолтных" вопросов

2. **Гибкость**
   - Можно настроить время для любого вопроса
   - Можно сбросить на глобальное в любой момент
   - Работает одинаково при создании и редактировании

3. **Безопасность**
   - Валидация диапазона (30-600 сек)
   - Шаг 30 секунд для удобства
   - Невозможно установить некорректное значение

## Примеры использования

### Кейс 1: Разная сложность вопросов

```
Вакансия: "Python Backend Developer"

Глобальное время: 180 сек (3 минуты)

Вопросы:
  1. "Расскажите о себе" → 120 сек (простой)
  2. "Опишите опыт работы с Django" → 180 сек (глобальное)
  3. "Решите алгоритмическую задачу" → 420 сек (7 минут - сложный)
  4. "Какие проекты делали?" → 180 сек (глобальное)
```

### Кейс 2: Вопросы с материалами

```
Вопрос: "Посмотрите видео о нашей компании (3 мин) и расскажите, что вас привлекло"

Время: 420 сек (7 минут)
  - 3 минуты на просмотр
  - 4 минуты на ответ
```

### Кейс 3: Критические вопросы

```
Вопрос: "Red Flag: Опишите конфликтную ситуацию с коллегой"

Время: 300 сек (5 минут)
  - Критический вопрос требует детального ответа
  - Больше времени = более взвешенный ответ
```

## Обратная совместимость

✅ **Старые вакансии** — автоматически используют `maxTime` из первого вопроса как глобальное  
✅ **Новые вакансии** — все вопросы создаются с глобальным временем  
✅ **Миграция не требуется** — поле `maxTime` уже существует в БД
